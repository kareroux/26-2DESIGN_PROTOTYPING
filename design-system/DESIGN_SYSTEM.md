# 어항 Design System v1.0

인터랙티브 오브제 조명 **어항**과 그 제품 웹사이트를 위한 디자인시스템.

| | |
|---|---|
| 제품 | 어항 — 손의 움직임에 반응하는 인터랙티브 오브제 조명 |
| 참고 사이트 | landonorris.com (구조와 위계), t-able.org (절제 규칙) |
| 토큰 원본 | `tokens.json` |
| 적용 대상 | 제품 소개 웹사이트, 스크롤 조립 씬, 센서 대시보드 |

---

## 1. 브랜드 원칙

### 1.1 빛이 유일한 색입니다
배경은 검정, 글자는 따뜻한 흰색, 그리고 색은 **하나뿐입니다 — 호박색 `#FFA850`**.
이 값은 임의로 고른 색이 아니라 램프 3D 씬의 실제 광원 값(`lampLight 0xFFA850`)이고,
본문 흰색 `#F5F2EC`는 키 라이트 값(`0xFFF3E0`)에서 파생됐다.
화면의 색과 실물의 빛이 같은 숫자를 씁니다.

### 1.2 호박색은 장식이 아니라 신호입니다
호박색은 **상태가 켜져 있을 때만** 씁니다 — 활성, 선택, 포커스, 점등, 센서 반응.
한 화면에서 호박색 면적은 **5%를 넘지 않습니다**. 넘으면 신호가 아니라 배경이 됩니다.
t-able.org가 순수 빨강 하나를 도장처럼만 쓰는 방식을 그대로 가져왔습니다.

### 1.3 수치는 숨기지 않습니다
치수, 좌표, 센서값, 진행률은 **mono 서체로 그대로 노출합니다**.
제품이 실측 3D 모델(188.5 × 90.8 × 242.0 mm)에서 나왔기 때문에,
숫자를 보여주는 것이 이 제품의 설득력입니다.

### 1.4 움직임은 물리를 따릅니다
부품은 튕기지 않습니다. 미끄러져 제자리에 들어갑니다.
조립 모션은 `easing/physical`, UI 모션은 `easing/standard`를 씁니다.

### 1.5 비어 있음은 실패가 아닙니다
여백은 채워야 할 공간이 아닙니다. 검은 바탕이 곧 조명의 무대입니다.

## 2. 토큰

### 2.1 색상 토큰

**원시 토큰 (primitive)** — 값 그 자체. 컴포넌트에서 직접 쓰지 않습니다.

| 토큰 | 값 | 비고 |
|---|---|---|
| `ink-000` | `#000000` | 캔버스 |
| `ink-050` | `#0A0A0B` | 표면 |
| `ink-100` | `#141416` | 들린 표면 |
| `ink-400` | `#44464C` | 비활성 글자 |
| `ink-500` | `#7D808A` | 보조 글자 |
| `ink-700` | `#C7C9CE` | 본문 보조 |
| `ink-900` | `#F5F2EC` | 본문 |
| `amber-500` | `#FFA850` | **신호색**. 램프 점등값 |
| `amber-400` | `#FFC27A` | hover |
| `amber-600` | `#E08A33` | press |
| `warm-white` | `#FFF3E0` | 키 라이트 |
| `alert-500` | `#FF4A3D` | 오류 |
| `ok-500` | `#6FD08C` | 성공 |

**의미 토큰 (semantic)** — 컴포넌트는 반드시 이 층만 참조합니다.

| 토큰 | 참조 | 용도 |
|---|---|---|
| `bg/canvas` | `ink-000` | 페이지 바탕 |
| `bg/surface` | `ink-050` | 카드와 입력 필드 |
| `bg/raised` | `ink-100` | 모달과 팝오버 |
| `bg/signal` | `amber-500` | Primary 버튼 바탕 |
| `fg/primary` | `ink-900` | 본문 |
| `fg/secondary` | `ink-700` | 설명문 |
| `fg/muted` | `ink-500` | 캡션과 라벨 |
| `fg/on-signal` | `ink-000` | 호박색 위 글자 |
| `fg/signal` | `amber-500` | 링크와 활성 라벨 |
| `border/hairline` | `rgba(245,242,236,0.12)` | 카드 경계 |
| `border/default` | `rgba(245,242,236,0.20)` | 입력 필드 |
| `border/signal` | `amber-500` | 포커스와 선택 |
| `bg/hover-subtle` | `rgba(245,242,236,0.06)` | Secondary 버튼 hover |
| `bg/signal-subtle` | `rgba(255,168,80,0.14)` | 태그 바탕 |
| `focus/ring` | `amber-500` | 키보드 포커스 |
| `glow/signal` | `rgba(255,168,80,0.45)` | 점등 효과 |

**명암비** — `fg/primary` on `bg/canvas` = 18.8:1. `fg/secondary` = 12.7:1. `fg/muted` = 5.3:1 (표면 위 5.0:1).
`fg/on-signal` on `bg/signal` = 11.0:1. 본문 등급 모두 WCAG AA 이상.
`fg/signal`(호박색 글자)은 **16px 이상에서만** 씁니다.

### 2.2 타이포그래피 토큰

| 역할 | 서체 | 용도 |
|---|---|---|
| display | Archivo | 큰 제목 |
| text | IBM Plex Sans KR | 본문과 한글 |
| mono | IBM Plex Mono | 라벨, 수치, HUD |

서체 두께는 **400 / 500 / 700 세 가지만** 씁니다.
t-able.org가 두 가지로 사이트 전체를 운용한 절제를 기준으로 삼았습니다.

**크기 스케일** — 11, 12, 14, 16, 20, 24, 32, 48, 64, 96 px

**자간** — 큰 제목일수록 좁힌다. display `-0.03em`, heading `-0.015em`, 본문 `0`, mono 라벨 `+0.12em`.
landonorris.com의 음수 자간 처리를 그대로 가져온 규칙입니다.

**텍스트 스타일**

| 스타일 | 서체 / 크기 / 두께 / 행간 |
|---|---|
| `display/xl` | Archivo 96 / 700 / 1.05 |
| `display/lg` | Archivo 64 / 700 / 1.05 |
| `heading/xl` | Archivo 48 / 700 / 1.25 |
| `heading/lg` | Archivo 32 / 500 / 1.25 |
| `heading/md` | Plex Sans KR 24 / 500 / 1.25 |
| `body/lg` | Plex Sans KR 20 / 400 / 1.55 |
| `body/md` | Plex Sans KR 16 / 400 / 1.55 |
| `body/sm` | Plex Sans KR 14 / 400 / 1.75 |
| `label/md` | Plex Mono 12 / 500 / 대문자 / +0.12em |
| `label/sm` | Plex Mono 11 / 500 / 대문자 / +0.12em |
| `data/md` | Plex Mono 16 / 400 — 치수와 센서값 |

한글은 `display` 서체를 쓰지 않습니다. 한글 제목은 `heading/md` 이하로 Plex Sans KR을 씁니다.

### 2.3 간격과 반경 토큰

**간격** — 4px 배수. `0, 4, 8, 12, 16, 24, 32, 48, 64, 96, 128, 192`
중간값을 만들지 않습니다. 22px가 필요하면 설계가 틀린 것입니다.

**반경** — `0, 2, 4, 8, 12, 999`
알루미늄 프로파일과 3D 프린트 부품이 제품이므로 반경은 작게 유지합니다.
`999`(pill)는 태그와 상태 뱃지에만 씁니다.

**선 두께** — hairline `1px`, thick `2px` 두 가지.

### 2.4 브레이크포인트와 그리드

| 이름 | 최소폭 | 컬럼 | 거터 | 바깥 여백 |
|---|---|---|---|---|
| sm | 480px | 4 | 16px | 16px |
| md | 768px | 8 | 24px | 32px |
| lg | 1024px | 12 | 24px | 48px |
| xl | 1440px | 12 | 32px | 64px |

최대 콘텐츠 폭 `1440px`. 그 이상에서는 가운데 정렬하고 바깥을 비웁니다.

### 2.5 모션 규칙

| 토큰 | 값 | 용도 |
|---|---|---|
| `duration/instant` | 80ms | 눌림 피드백 |
| `duration/fast` | 160ms | hover, 색 변화 |
| `duration/base` | 240ms | 일반 전환 |
| `duration/slow` | 480ms | 패널과 모달 |
| `duration/scene` | 900ms | 스크롤 조립 씬 |

| 토큰 | 값 | 용도 |
|---|---|---|
| `easing/standard` | `cubic-bezier(0.2,0,0,1)` | 기본 |
| `easing/enter` | `cubic-bezier(0,0,0,1)` | 등장 |
| `easing/exit` | `cubic-bezier(0.4,0,1,1)` | 퇴장 |
| `easing/physical` | `cubic-bezier(0.33,1,0.68,1)` | 부품 조립 |

**규칙**
- 색과 투명도는 애니메이션합니다. 레이아웃 속성(width, top)은 하지 않습니다.
- 한 화면에서 **독립적으로** 움직이는 UI 요소는 **3개 이하**.
  3D 씬의 한 효과를 이루는 여러 스프라이트는 하나로 셉니다. 커서를 따라오는
  배경 오브 6개가 그런 경우이고, 서로 다른 지연으로 같은 목표를 따라가므로
  사용자에게는 궤적 하나로 보입니다.
- `prefers-reduced-motion`에서는 transform 애니메이션을 모두 제거하고 opacity만 남깁니다.
- 스크롤 씬은 스크롤 위치에 **직접 연동**합니다. 스크롤과 무관한 자동 재생은 쓰지 않습니다.
- 점등은 밝기를 선형으로 올리지 않습니다. 직전에 주변광을 떨어뜨리고, 두 번 깜빡인 뒤
  한 번 과하게 올라왔다가 제 밝기로 가라앉습니다. 스크롤 위치에만 의존하므로
  되감으면 그대로 되돌아갑니다.
- 커서 추종은 점등이 끝난 뒤에만 작동합니다. 그 전에는 커서에 반응하지 않습니다.

## 3. 컴포넌트

### 3.1 버튼

공통: 반경 `4px`, 서체 `label/md`(mono 대문자), 아이콘 간격 `8px`,
포커스 링 `2px solid amber-500`, offset `2px`.

| 크기 | 높이 | 좌우 패딩 |
|---|---|---|
| sm | 32px | 12px |
| md | 40px | 16px |
| lg | 48px | 24px |

**Primary** — 화면당 **하나만**. 주된 행동 하나에만 씁니다.

| 상태 | 바탕 | 글자 | 테두리 |
|---|---|---|---|
| default | `amber-500` | `ink-000` | 없음 |
| hover | `amber-400` | `ink-000` | 없음 |
| pressed | `amber-600` | `ink-000` | 없음 |
| disabled | `ink-200` | `fg/disabled` | 없음 |
| loading | `amber-600` | `ink-000` | mono 점 3개 애니메이션 |

**Secondary** — 대등한 선택지. 한 화면에 여럿 가능.

| 상태 | 바탕 | 글자 | 테두리 |
|---|---|---|---|
| default | 투명 | `fg/primary` | `border/default` |
| hover | `rgba(245,242,236,0.06)` | `fg/primary` | `border/strong` |
| pressed | `rgba(245,242,236,0.12)` | `fg/primary` | `border/strong` |
| disabled | 투명 | `fg/disabled` | `border/hairline` |

**Utility** — 보조 행동. 아이콘 단독 또는 짧은 글자.

| 상태 | 바탕 | 글자 |
|---|---|---|
| default | 투명 | `fg/muted` |
| hover | 투명 | `fg/primary` |
| pressed | 투명 | `fg/signal` |
| disabled | 투명 | `fg/disabled` |

**variant 축**: `type`(primary, secondary, utility) × `size`(sm, md, lg) ×
`state`(default, hover, pressed, disabled, loading) × `icon`(none, leading, trailing, only)

### 3.2 입력 필드와 텍스트 영역

높이 `44px`, 패딩 `12px / 16px`, 반경 `4px`,
바탕 `bg/surface`, 테두리 `border/default`, 서체 `body/md`.
라벨은 필드 위 `8px`, 서체 `label/sm`.
텍스트 영역은 최소 높이 `120px`, 세로 리사이즈만 허용.

| 상태 | 테두리 | 그 외 |
|---|---|---|
| default | `border/default` | — |
| hover | `border/strong` | — |
| focus | `border/signal` 1px + 같은 색 box-shadow 1겹 | 두께 2px 로 보이되 레이아웃이 밀리지 않습니다 |
| filled | `border/default` | 글자 `fg/primary` |
| error | `border/error` | 아래 `alert-500` 메시지, `body/sm` |
| disabled | `border/hairline` | 바탕 `ink-000`, 글자 `fg/disabled` |

도움말은 필드 아래 `8px`, `fg/muted`, `body/sm`.
오류 메시지는 **무엇이 틀렸는지가 아니라 어떻게 고치는지**를 씁니다.

**variant 축**: `type`(text, textarea) × `state`(6종) × `label`(있음, 없음) × `help`(있음, 없음)

### 3.3 프로젝트 카드

| 항목 | 값 |
|---|---|
| 바탕 | `bg/surface` |
| 테두리 | `border/hairline` 1px |
| 반경 | `8px` |
| 패딩 | `24px` |
| 내부 간격 | `16px` |
| 이미지 비율 | `4 : 3` |
| hover | 테두리 `border/signal`, `glow` 그림자, 160ms |

**구조 (위에서 아래로)**
1. 이미지 — 4:3, 반경 `4px`
2. 라벨 — `label/sm`, `fg/muted` (예: `PRODUCT 2026`)
3. 제목 — `heading/md`, `fg/primary`
4. 설명 — `body/sm`, `fg/secondary`, 최대 3줄
5. 메타 — `data/md`, `fg/muted` (치수, 소재)

**variant 축**: `size`(sm, md, lg) × `media`(image, none) × `state`(default, hover, focus) ×
`emphasis`(default, featured — featured는 테두리를 `border/signal`로 고정)

### 3.4 레이아웃 그리드와 섹션 규칙

- 모든 콘텐츠는 그리드 컬럼에 정렬합니다. 임의 위치를 쓰지 않습니다.
- 섹션 세로 패딩: sm `64px`, md `96px`, lg `128px`
- 섹션 머리말(라벨 + 제목 + 설명) 내부 간격 `24px`
- 본문 글줄은 **12컬럼 중 8컬럼을 넘지 않습니다**
- 한 섹션에 Primary 버튼은 하나
- 전체 폭 이미지는 그리드를 벗어나도 되지만, 그 위의 글자는 그리드를 지킵니다

**표준 섹션 구조**

```
[heading/xl, fg/primary]    ← 제목. 내용이 이미 말하는 것을 반복하지 않습니다
[body/lg, fg/secondary]     ← 더할 정보가 있을 때만. 없으면 생략
[간격 48px]
[콘텐츠: 카드 그리드 / 이미지 / 3D 씬]
```

제목 위에 작은 분류 라벨을 덧붙이지 않습니다. 「제품 소개」처럼 아래 내용이
이미 말하고 있는 제목도 쓰지 않습니다. 제목이 더할 말이 없으면 제목을 뺍니다.

## 4. 사용 가이드와 정책

### 4.1 반드시 지킬 것
- 컴포넌트는 **의미 토큰만** 참조합니다. 원시 토큰을 직접 쓰지 않습니다.
- 토큰에 없는 색, 간격, 반경을 새로 만들지 않습니다. 필요하면 토큰을 먼저 고칩니다.
- 호박색은 상태가 켜졌을 때만. 화면당 면적 5% 이하.
- 모든 상호작용 요소는 키보드 포커스가 보여야 합니다.
- 터치 대상은 최소 `44 × 44px`.

### 4.2 하지 말 것
- 그라데이션 배경. 빛은 3D 씬에서만 납니다.
- 두 번째 강조색 추가.
- 호박색을 큰 면적의 바탕으로 사용.
- 한글 제목에 display 서체 적용.
- 색만으로 상태를 전달 (아이콘이나 글자를 함께 씁니다).
- 토큰을 거치지 않은 하드코딩 값.
- 제목 위 장식 라벨, 내용을 되풀이하는 소제목.
- 중점(·). 나열은 쉼표나 줄바꿈으로.
- 바로 아래 내용이 이미 보여주는 것을 앞세워 말하는 리드 문장.
- 위 문단을 되풀이하는 인용구.

### 4.3 토큰 변경 절차
1. `tokens.json`을 고칩니다 (단일 원본)
2. 영향을 받는 컴포넌트를 표시합니다
3. 명암비를 다시 확인합니다
4. 버전을 올립니다 — 색과 간격 값 변경은 minor, 토큰 이름 변경과 삭제는 major

### 4.4 접근성 기준
- 본문 명암비 4.5:1 이상, 큰 글자 3:1 이상
- 포커스 링은 제거하지 않습니다
- `prefers-reduced-motion` 지원 필수
- 3D 씬에는 대체 텍스트 설명을 둡니다

## 6. 적용 범위와 상위 규칙과의 관계

이 디자인시스템은 **제품 소개 웹사이트(스크롤 조립 씬 + 제품 페이지)** 에만 적용됩니다.
수업에서 제공된 `reference/Guidelines.md`(「IoT 조명 웹앱 기본 프레임」)는
**어항 Supabase 웹앱**에 적용되는 별도 규칙이며, 두 문서는 대상이 다릅니다.

### 6.1 두 문서가 합의하는 것

원칙 층위에서는 충돌이 없습니다.

| 항목 | Guidelines.md | 본 문서 |
|---|---|---|
| 색, 크기, 간격은 토큰(CSS 변수)만 | 시각 규칙 7 | §4.1 |
| 임의 hex 값 금지 | 시각 규칙 7 | §4.2 |
| 터치 대상 최소 44px | 동작 규칙 2 | §4.1 |
| 텍스트 대비 4.5:1 이상 | 동작 규칙 5 | §4.4 |
| 상태를 색만으로 전달 금지 | 동작 규칙 1 | §4.2 |
| 검은 바탕 단일 테마 | 동작 규칙 5 | §1.1 |
| 무의미한 소제목과 장식 라벨 금지 | 시각 규칙 4 | §3.4, §4.2 |
| 중점(·) 금지, 나열은 쉼표로 | 시각 규칙 5 | §4.2 |

### 6.2 두 문서가 다른 것

| 항목 | Guidelines.md (어항 웹앱) | 본 문서 (제품 사이트) |
|---|---|---|
| 카드 UI | 금지 | 프로젝트 카드 사용 (§3.3) |
| 사각 프레임 테두리 | 금지 | 카드와 입력 필드에 사용 |
| 라운드 | `border-radius: 0` | 2, 4, 8, 12px (§2.3) |
| letter-spacing, line-height | 폰트 기본값 | 토큰으로 지정 (§2.2) |
| 대문자 라벨 | 금지 | mono 대문자 라벨 사용 |
| 구분선, 그림자 | 금지 | 섹션 구분선, 점등 글로우 사용 |

시각 규칙 4(무의미한 소제목과 장식 라벨 금지)와 5(중점 금지)는 처음에 차이 항목으로
분류했으나, 둘 다 시각 언어의 선택이 아니라 글쓰기 규칙이므로 두 문서 모두에
적용됩니다. 섹션 라벨 10개, 중점 전부, 리드 문장 1개와 인용구 1개를 제거했습니다.

차이는 목적에서 옵니다. 어항 웹앱은 **센서값을 읽는 계기판**이라 화면에서 요소를
덜어낼수록 값이 또렷해집니다. 제품 소개 사이트는 **설명하는 문서**라 내용을 묶고
구분하는 장치가 필요하고, 과제 요건 자체가 버튼, 입력 필드, 프로젝트 카드를
포함하도록 지정하고 있습니다.

두 규칙을 한 화면에서 섞지 않습니다. 어항 웹앱 화면을 수정할 때는
`reference/Guidelines.md`를 따릅니다.
